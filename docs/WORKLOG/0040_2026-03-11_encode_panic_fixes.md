# Work Log 0040 — Encode Panic Fixes: FSM Skip List + DealFinalize Hand-Write

**Date**: 2026-03-11
**Status**: Complete

---

## Problem

Six encode functions contained reachable or unreachable panics:

| Function | Problem |
|---|---|
| `EncodeSkillUse` | Unreachable panic — `case packetver >= 0` always true. No fix needed. |
| `EncodeActorAction` | Unreachable panic — `case packetver >= 0` always true. No fix needed. |
| `EncodeGameLogin` | Always panics — empty `switch {}` |
| `EncodeMapLoaded` | Always panics — empty `switch {}` |
| `EncodeTimeSyncResponse` | Always panics — empty `switch {}` |
| `EncodeDealFinalize` | Always panics — empty `switch {}` |

---

## Root Cause Analysis

**`EncodeGameLogin`, `EncodeMapLoaded`, `EncodeTimeSyncResponse`**

These actions have send-direction impls whose underlying structs are header-only
packets — they appear only as raw `parseable_packet(id, len, handler, ...)` entries
in `clif_packetdb.hpp` with no corresponding C struct in `packets_struct.hpp`.
`resolveLayout` returns nil for all impls, so the dispatcher generates an empty
`switch {}` followed by a panic.

More fundamentally, these three packets are built directly by `pkg/fsm/packets.go`:
- `game_login` → `buildCharEnterPacket()` → `0x0065`/`0x0275`
- `map_loaded` → `buildMapLoadedPacket()` → `0x007D`
- `time_sync_response` → `buildTickSyncPacket()` → `0x007E`/`0x0360`

The generated encode functions were dead code that would never be called.

**`EncodeDealFinalize`**

`deal_finalize` has two impls: `0x00EB` (CZ, send) and `0x00EC` (ZC, receive).
`GenerateEncodeFile` checked `len(a.Implementations)` before filtering to
send-direction, so it always took the multi-impl dispatcher path even though only
one impl was a send packet. The dispatcher then filtered internally to one send
impl, resolved its layout as nil (no struct for `0x00EB`), and emitted an empty
switch.

`0x00EB` (`PACKET_CZ_CONCLUDE_EXCHANGE_ITEM`) is a 2-byte header-only packet —
`parseable_packet(0x00eb,2,clif_parse_TradeOk,0)` in `clif_packetdb.hpp` — with
no C struct definition.

## Fixes

### Fix 1 — FSM-owned action skip list (`internal/codegen/gen/encode.go`)

Added `fsmOwnedActions` map in `GenerateEncodeDirFiles`. Actions in this set are
skipped during encode generation and recorded in the skipped list. The three
FSM-owned actions (`game_login`, `map_loaded`, `time_sync_response`) are added.

```go
fsmOwnedActions := map[string]bool{
    "game_login":         true, // built by buildCharEnterPacket in pkg/fsm/packets.go
    "map_loaded":         true, // built by buildMapLoadedPacket in pkg/fsm/packets.go
    "time_sync_response": true, // built by buildTickSyncPacket in pkg/fsm/packets.go
}
```

**Effect**: `pkg/encode/game_login.go`, `pkg/encode/map_loaded.go`, and
`pkg/encode/time_sync_response.go` are no longer generated. Future codegen runs
will not recreate them.

### Fix 2 — Pre-filter send impls in `GenerateEncodeFile` (`internal/codegen/gen/encode.go`)

`GenerateEncodeFile` now filters `a.Implementations` to send-direction only
**before** the `len == 1` vs `len > 1` branch. This correctly identifies
`deal_finalize` as a single-send-impl action and routes it through
`generateEncodeFunc` rather than `generateEncodeDispatcher`.

```go
// Before: checked len(a.Implementations) — counted ZC impls too
if len(a.Implementations) == 1 { ... } else { dispatcher }

// After: filter first, then branch on filtered count
sendImpls := filterSendImpls(a.Implementations)
if len(sendImpls) == 0 { return error }
if len(sendImpls) == 1 { generateEncodeFunc } else { dispatcher with sendAction }
```

`generateEncodeDispatcher` retains its own internal filter as a safety net but
it is now redundant for all callers that go through `GenerateEncodeFile`.

### Fix 3 — Hand-written `EncodeDealFinalize` (`pkg/encode/deal_finalize.go`)

`PACKET_CZ_CONCLUDE_EXCHANGE_ITEM` (`0x00EB`) has no rAthena C struct — it is a
2-byte packet type only. After fix 2, the single send impl routes to
`generateEncodeFunc`, which calls `resolveLayout` and returns an error (nil
layout). So the file is still skipped by codegen.

Hand-written instead:

```go
func EncodeDealFinalize(_ send.DealFinalize, _ uint32) [2]byte {
    return [2]byte{0xeb, 0x00}
}
```

The file header omits `// Code generated by internal/codegen. DO NOT EDIT.` so
`cleanGeneratedDir` preserves it across future codegen runs.
