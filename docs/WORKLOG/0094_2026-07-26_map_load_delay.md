# 0094 — MapLoadDelay: Configurable Delay Before LoadEndAck

**Date:** 2026-07-26  
**PR:** #22  
**Type:** Feature  
**Status:** Pending review

## Problem

The FSM sends CZ_NOTIFY_ACTORINIT (0x007D, LoadEndAck) with zero delay after
receiving ZC_ACCEPT_ENTER. Normal clients have a 200-500ms rendering delay
between map entry and LoadEndAck. Bot frameworks that send LoadEndAck
immediately can trigger a server-side race condition in rAthena:

1. Map-server receives LoadEndAck → clears `connect_new` flag
   (clif.cpp:10754)
2. Char-server's async register sync (PC_DIE_COUNTER) arrives
   (intif.cpp:1474 → set_reg_num → pc_setparam)
3. `pc_setparam` sees `connect_new == 0` → triggers `status_calc_pc`
   (pc.cpp:10628-10630)
4. `status_calc_pc` dereferences `sd->bonus.hp` before session data is fully
   populated → SIGSEGV (status.cpp:3138)

This only manifests with wire-speed clients (no rendering delay) + Super
Novice characters + `die_counter == 1`.

Discovered during a 100-bot load test: map-server crashed 34 times with
SIGSEGV in `status_get_hpbonus` / `status_calc_regen`.

## Solution

Add `ServerConfig.MapLoadDelay time.Duration` field. When set, the FSM waits
the specified duration (context-cancellable) before sending LoadEndAck in the
`onMapEnter` handler. Defaults to 0 (backward compatible).

Recommended value: 500ms.

## Implementation

- `pkg/session/fsm.go`: Added `MapLoadDelay` to `ServerConfig`. In
  `onMapEnter`, use `select` with `time.After` and `ctx.Done()` so the delay
  is interruptible by context cancellation.
- `docs/DESIGN/HLD.md`: Updated ServerConfig listing (§3), map-enter state
  sequence (§4), and usage example.

## Test Results

- `TestConnect_MapLoadDelay_AppliedBeforeLoadEndAck/no_delay` — elapsed 0ms,
  asserts <100ms (PASS)
- `TestConnect_MapLoadDelay_AppliedBeforeLoadEndAck/300ms_delay` — elapsed
  300ms, asserts 250ms-1s (PASS)
- `TestConnect_MapLoadDelay_CancelledByContext` — Connect returns after 200ms
  with `context canceled` error (PASS)
- Full session test suite: PASS (0.510s)

## goKore Integration

goKore sets `MapLoadDelay: 500 * time.Millisecond` in connector.go. The
rathena-side patches (null checks in status.cpp/pc.cpp) remain as
defense-in-depth but are no longer triggered with the delay in place.
