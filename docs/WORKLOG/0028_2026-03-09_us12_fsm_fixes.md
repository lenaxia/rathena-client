**Note on TestConnect_ContextCancelled**: The FSM already passes `ctx` to the dialer. With a ctx-aware dialer stub (which checks `ctx.Done()` in a select), the test passes even before any FSM changes. The test documents the current FSM contract: context cancellation is the dialer's responsibility. A production dialer using `net.DialContext` will respect ctx automatically.

### Test design for Bug 12-B (writeErr):

Used `failAfterNWritesConn` wrapper (in fsm_test.go) that allows `allowedWrites=2` writes on the char conn (CH_ENTER + first 0x09A1), then fails the third (second 0x09A1). The server-side goroutine stays open (sleeping 10s) so the conn isn't EOF'd — this forces the bug to be a timeout, not an immediate EOF.

## Bug Fixes

### Bug 12-A — `pagesTotal` stores character count, not page count

**Before:**
```go
// charPhaseResult struct:
pagesTotal   uint32 // total pages expected (from 0x09A0)

// 0x09A0 handler:
res.pagesTotal = total // rAthena sends one page per char in practice; we treat total == pages

// 0x099D handler completion check:
if res.got09A0 && res.pagesRecv >= res.pagesTotal {
```

**After:**
```go
// charPhaseResult struct:
charsExpected uint32 // total from 0x09A0; we send one CH_CHARLIST_REQ per character

// 0x09A0 handler:
// total is the character count from 0x09A0; we send one CH_CHARLIST_REQ per
// character and expect one 0x099D response per character (rAthena sends one
// char per page in practice).
res.charsExpected = total

// 0x099D handler completion check:
if res.got09A0 && res.pagesRecv >= res.charsExpected {
```

### Bug 12-B — Write errors discarded in 0x09A0 handler

**Before:**
```go
for i := uint32(0); i < total; i++ {
    pkt := buildCharlistReq()
    _ = writeDeadline(conn, pkt, f.stepTimeout())  // error discarded
}
```

**After:**
```go
var writeErr error
charSess.RegisterHandler(0x09A0, func(data []byte, pv uint32) {
    // ...
    for i := uint32(0); i < total; i++ {
        pkt := buildCharlistReq()
        if err := writeDeadline(conn, pkt, f.stepTimeout()); err != nil {
            writeErr = err
            return
        }
    }
})
// In feed loop, check writeErr at top of each iteration:
for !res.done {
    if writeErr != nil {
        return "", fmt.Errorf("fsm: send charlist req: %w", writeErr)
    }
    // ...
}
// Also check after loop exits:
if writeErr != nil {
    return "", fmt.Errorf("fsm: send charlist req: %w", writeErr)
}
```

### Bug 12-D — `stepTimeout()` fallback unreachable dead code

**Before:**
```go
// In New():
server.StepTimeout = 30 * time.Second  // magic literal (one site)

// stepTimeout():
func (f *ConnectionFSM) stepTimeout() time.Duration {
    if f.server.StepTimeout > 0 {
        return f.server.StepTimeout
    }
    return 30 * time.Second  // magic literal (second site) — dead code
}
```

**After:**
```go
const defaultStepTimeout = 30 * time.Second  // named constant, appears once

// In New(): server.StepTimeout = defaultStepTimeout

// stepTimeout() simplified:
func (f *ConnectionFSM) stepTimeout() time.Duration {
    return f.server.StepTimeout
}
```

`30 * time.Second` now appears exactly once in `fsm.go` (as the `defaultStepTimeout` constant value).

### Bug 12-E — `conn` leak in `runMapPhase` when `onReady` is nil

## Surprises

1. **TestConnect_ContextCancelled**: The test passes before and after the fix because the FSM already passes `ctx` to the dialer call, and the ctx-aware dialer stub handles cancellation. No FSM-level ctx check was needed. Test documents the current contract correctly.

2. **Bug 12-B timing**: The `writeErr` check must be at the TOP of the `for !res.done` loop (before feedStep), not only after the loop. If checked only after the loop, feedStep would time out first (the server-side conn stays open but sends nothing), returning "i/o timeout" before the `writeErr` check is reached.

3. **failAfterNWritesConn**: A custom `net.Conn` wrapper was needed because net.Pipe closes both read and write when one side closes. Closing the server side would give the FSM an EOF read (not a timeout), which wouldn't distinguish the bug scenario. The wrapper allows writes to fail while leaving reads working (server stays open, sleeping).
