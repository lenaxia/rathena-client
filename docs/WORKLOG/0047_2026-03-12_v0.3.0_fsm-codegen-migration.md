# 0047 — v0.3.0: FSM migrated to generated encode functions

**Date**: 2026-03-12
**Tag**: v0.3.0
**Commit**: d64f5e4

---

## Goal

Fix FR-0046: goKore loses its TCP connection ~4 seconds after a same-server warp
(`0x0091 ZC_NPCACK_MAPMOVE`) because the required warp-ack packets (`0x007D` +
`0x007E`/`0x0360`) are never sent.

Root cause traced to the codegen pipeline: `map_loaded`, `time_sync_response`, and
`game_login` were suppressed from codegen by `fsmOwnedActions`, leaving those encode
functions absent from `pkg/encode/`. Additionally, several semantics DB entries had
wrong `rathena_struct` names, preventing the injector from finding the correct structs
in the VersionTable.

The decision was made to fix the entire codegen pipeline for all FSM packets rather
than patching individual files by hand, and to migrate `fsm.go` fully away from the
handwritten `build*` functions to the generated `encode.Encode*` API.

---

## Root Causes Found and Fixed

### 1. `fsmOwnedActions` suppressing codegen (`internal/codegen/gen/encode.go`)

`map_loaded`, `time_sync_response`, and `game_login` were listed in `fsmOwnedActions`,
a blocklist that prevented codegen from generating `pkg/encode/` files for them. This
was the direct cause of the missing `EncodeMapLoaded` and `EncodeTimeSyncResponse`
functions that goKore needed.

**Fix**: removed all three from `fsmOwnedActions`.

### 2. `injectCommonPacketStructs` missing `PACKET_CH_` and `PACKET_CA_` prefixes (`internal/codegen/main.go`)

The injector only processed structs with `PACKET_CZ_` and `PACKET_ZC_` prefixes.
`PACKET_CH_` (char→server) and `PACKET_CA_` (client→auth) structs were never injected
into the VersionTable, so codegen could not find their sizes or field layouts.

**Fix**: added `PACKET_CH_` and `PACKET_CA_` to the `commonPrefixes` list.

### 3. Wrong `rathena_struct` names in semantics DB (`semantics/mappings.yaml`)

Five action entries had `PACKET_CZ_*` or `PACKET_CH_ENTER_0x0065` as their
`rathena_struct`, but the actual structs used are synthetic (`SYNTH_*`) because rAthena
parses those packets with raw `RFIFOSKIP` macros rather than named structs.

| Action | Was | Fixed to |
|---|---|---|
| `map_loaded` | `PACKET_CZ_NOTIFY_ACTORINIT` | `SYNTH_CZ_NOTIFY_ACTORINIT` |
| `time_sync_response` (0x007E) | `PACKET_CZ_REQUEST_TIME` | `SYNTH_CZ_REQUEST_TIME` |
| `time_sync_response` (0x0360) | `PACKET_CZ_REQUEST_TIME2` | `SYNTH_CZ_REQUEST_TIME2` |
| `game_login` | `PACKET_CH_ENTER_0x0065` | `SYNTH_CH_ENTER_0x0065` |
| `map_login` | `PACKET_CZ_ENTER` | `SYNTH_CZ_ENTER` |

All five `SYNTH_*` structs were already present in `internal/codegen/synthetic_structs.hpp`
— no new structs were needed.

### 4. Stale duplicate `request_time` action

A `request_time` semantics action existed alongside `time_sync_response` and mapped
to a single-version (no packetver dispatch) stub. It was a duplicate with incorrect
behaviour (always emitted `0x007E`, ignoring packetver). Deleted along with its
generated `pkg/encode/request_time.go` and `pkg/send/request_time.go`.

## Work Done

### Codegen fixes

- `internal/codegen/gen/encode.go`: removed `map_loaded`, `time_sync_response`,
  `game_login` from `fsmOwnedActions`.
- `internal/codegen/main.go`: added `PACKET_CH_`, `PACKET_CA_` to `commonPrefixes`.
- `semantics/mappings.yaml`: fixed 5 struct names; deleted `request_time` action.
- Re-ran codegen → 22 new `pkg/encode/` files generated; `request_time.go` deleted.
- `pkg/send/` structs populated with fields for all 22 new encode functions.

### FSM migration (`pkg/fsm/fsm.go`)

All seven `build*` call sites replaced with generated `encode.Encode*` calls:

| Old | New |
|---|---|
| `buildLoginPacket(pv, user, pass)` | `encode.EncodeMasterLogin(send.MasterLogin{...}, pv)[:]` |
| `buildCharEnterPacket(aid, sid1, sid2, sex)` | `encode.EncodeGameLogin(send.GameLogin{...}, pv)[:]` |
| `buildCharlistReq()` | `encode.EncodeRequestCharacterPage(send.RequestCharacterPage{}, pv)[:]` |
| `buildSelectCharPacket(slot)` | `encode.EncodeCharLogin(send.CharLogin{Slot: slot}, pv)[:]` |
| `buildMapEnterPacket(aid, cid, sid1, sex)` | `encode.EncodeMapLogin(send.MapLogin{...}, pv)[:]` |
| `buildMapLoadedPacket()` | `encode.EncodeMapLoaded(send.MapLoaded{}, pv)[:]` |
| `buildTickSyncPacket(pv)` | `encode.EncodeTimeSyncResponse(send.TimeSyncResponse{ClientTime: 0}, pv)[:]` |

All encode functions return fixed-size arrays; sliced with `[:]` before passing to
`writeDeadline` or `encodePacketID`.

### Dead code removal

- `pkg/fsm/packets.go`: all `build*` functions deleted. Only `copyStr` retained.
- `pkg/fsm/fsm_test.go`: `TestBuild*` unit tests removed (dead, no longer callable).

### Test migration (`pkg/fsm/packets_test.go`)

Rewritten as external `package fsm_test` golden tests directly exercising the
generated encode functions. Covers field layout, null padding, all-slots, and
packetver dispatch boundaries for all 7 FSM C→S packets.

One fix needed: `const sid1 = uint32(0xDEADBEEF)` caused a typed-constant overflow
when passed as `AuthCode: int32(sid1)`. Fixed by using a variable instead:
`sid1 := int32(-559038737)` with the assertion updated to read back via `int32(...)`.

### VersionTable test (`internal/codegen/preprocess/vt_check_test.go`)

Extended to verify all 8 FSM structs are present in the VersionTable:
`PACKET_CA_LOGIN`, `SYNTH_CH_ENTER_0x0065`, `PACKET_CH_SELECT_CHAR`,
`PACKET_CH_CHARLIST_REQ`, `SYNTH_CZ_ENTER`, `SYNTH_CZ_NOTIFY_ACTORINIT`,
`SYNTH_CZ_REQUEST_TIME`, `SYNTH_CZ_REQUEST_TIME2`.

### Integration test fixes (`pkg/fsm/live_integration_test.go`)

Field references updated to match current event structs:
- `e.ID` → `e.GID` (`events.ActorExists`)
- `e.StatType` / `e.Value` → `e.VarID` / `e.Count` (`events.StatUpdate`)

## EPIC-06 Evaluation

A higher-level `SendSameServerWarpAck` helper API (EPIC-06) was considered and
rejected. The two packets goKore needs (`0x007D` + `0x007E`/`0x0360`) are now
both available as generated encode functions. goKore can call them directly with no
abstraction layer needed. EPIC-06 backlog doc retained for reference.
